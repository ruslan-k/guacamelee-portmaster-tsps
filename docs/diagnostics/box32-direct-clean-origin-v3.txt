Decision
--------
The 0x502 is not diagnostic-readback contamination: it persists with readback and
presenter disabled and is returned by native GLES. The immediate candidate is the
native glUniformMatrix4fv/program22 sequence, but the new argument marker needs one
repeat to prove whether the error is generated by that native call or a later call.
The next run should therefore repeat v3 with the rebuilt uniform-origin library,
then continue program18 all-vertex decoding and texture/FBO producer provenance.
