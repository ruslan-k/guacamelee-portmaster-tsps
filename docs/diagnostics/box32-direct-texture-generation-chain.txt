Missing proof
-------------
The current diagnostic build does not yet maintain a side table with:

  texture generation, object pointer, create/delete sequence,
  last CPU upload, last GPU writer, writer program generation, writer FBO generation

Therefore the following are NOT claimed:

  sampler uses deleted/reused generation: NOT PROVEN
  stale native texture mapping: NOT PROVEN
  expected writer targets A while sampler reads B: NOT PROVEN

The numeric chain is compatible with two explanations:

1. expected behavior: texture2/FBO2 is black before program86, so program86 correctly
   writes black; or
2. an unproven lifetime/binding issue causes program86 to read a different native
   texture than the logical render target.

The next implementation should add trace-only texture/FBO generation metadata and
last-writer events, then print the chain at program18/program86 sampler use. It must
not alter lookup, binding, FBO attachment, or presenter semantics.
