## Blocker state

Earlier live thread inspection showed the main thread in `R (running)` while the expected FBO guest texture lookup did not produce its post-lookup marker. The portable mutex A/B produced the same result. This is consistent with a guest-side emulation/dispatch execution boundary or a non-returning lookup path, but a production fix is not proven.

The next diagnostic must use guest/application-level call tracing or debugger-level PC/backtrace capture around the first FBO texture call. Do not add further FBO capability flags or presentation workarounds.
