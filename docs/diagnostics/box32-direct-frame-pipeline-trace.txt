## Binding classification

The logical and native FBO IDs match at the observed transitions:

```text
logical FBO3 -> native FBO3
logical FBO1 -> native FBO1
logical FBO2 -> native FBO2
logical default -> native default 0
```

No evidence of a logical/native FBO mismatch was found. `mainfbo=0` in the direct SDL/KMS path, and the gl4es GLX MainFBO path is not entered.

## Clear chronology

The first FBO3 draw occurs after a transparent black initial clear and is already black/transparent. The repeated later destination clear is internal to the blit shader path:

```text
ClearColor current=2 rgba=0,0,0,1
```

This occurs after the source is already black and therefore is not the cause of the first FBO3 failure. Default FBO receives occasional non-black UI/background samples (`109,167,160,255`), proving native default rasterization can produce pixels, but the game resolve destination remains black.

## Conclusion

The ordered trace shows:

```text
bind FBO3 correctly
→ native draw executes but FBO3 sample stays black
→ resolve reads black FBO1
→ resolve writes black FBO2
→ default/UI path may produce isolated non-black pixels
→ SDL swap is reached
```

The remaining boundary is draw provenance/state for the title/render pass, not FBO completeness or swap routing.
