## Runtime draw census limitation

The Box64 log at `BOX64_LOG=1` records GL symbol resolution but does not log every wrapped GL call. The following strings were resolved, not necessarily invoked as draw calls:

```text
glDrawArrays
glDrawElements
glDrawRangeElements
glMultiDrawArrays
glMultiDrawElements
glDrawArraysInstanced
glDrawElementsInstanced
glDrawElementsBaseVertex
glDrawRangeElementsBaseVertex
```

Therefore this log cannot prove a runtime draw count. No `GUA-DRAW` or equivalent application draw marker exists yet. The earlier `DrawArrays=0/DrawElements=0` count was only a grep over emitted wrapper calls and is not a complete draw census.

## Classification

The `0x8CD7` result is not immediately fatal: startup continues through archive, shader, and thread initialization. The `0x8CDD` transition on FBO 1 is a concrete unsupported-status event, but this log lacks attachment IDs/formats and cannot classify whether the transition is transient or persistent. The next diagnostic must instrument attachment lifecycle without consuming GL error state:

```text
Gen/Bind FBO
Gen/Bind texture or renderbuffer
storage dimensions/format
FramebufferTexture2D / FramebufferRenderbuffer
Check status
first runtime draw-family call
SDL_GL_SwapWindow
```

No FBO compatibility workaround was applied.
