## Texture provenance

FBO target textures:

```text
FBO3 color attachment: guest/native texture 89/89
FBO4 color attachment: guest/native texture 90/90
FBO5 color attachment: guest/native texture 91/91
```

Texture uploads:

```text
texture89 level0: 512x512, internal=0x84ee, data != NULL, mip levels present
texture90 level0: 1280x720, internal=0x8058, data = NULL
texture91 level0: 1280x720, internal=0x8058, data = NULL
texture92 level0: 1280x720, internal=0x8058, data = NULL
```

Numeric IDs are allocation-order dependent. In the sampled run the first FBO3 draw bound texture92 at texture unit 0; in another run the equivalent render-target binding was texture91. The stable fact is that the first FBO3 draw samples an empty render-target texture rather than a loaded content texture.

Texture91/92 are allocated as 1280x720 render targets with `data=NULL`; this is expected storage allocation but makes them unsuitable as non-black input until a prior pass fills them.

## Program/uniform provenance

Program21:

```text
link=successful
use=successful
native program=21
```

No `glUniform1i` calls were observed while guest program21 was active in the bounded uniform trace:

```text
GUA-UNIFORM1I program=21: 0
```

Therefore sampler assignment is not proven through `glUniform1i`; it may use another uniform family, cached/default state, or program21 may not be the expected texturing program for this first pass. This is the highest-value unresolved draw-state question.
