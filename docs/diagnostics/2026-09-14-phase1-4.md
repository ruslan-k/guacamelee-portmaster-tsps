Progress criterion: all four markers appear:

A final clean run with `DYNAREC=1`, `BIGBLOCK=0`, `BOX86_LOG=0`, diagnostics disabled reproduced the original stall (`game-bin` sleeping in `hrtimer_nanosleep`; log size 408 bytes).

Interpretation: the progress is caused by enabling `BOX86_LOG=1`, not by `BIGBLOCK=0`. This is timing-sensitive/instrumentation-sensitive behavior; logging is not being promoted as a production fix.

## Remaining blocker / guidance requested

The game enters a single-threaded 10 ms polling loop after two successful GL capability replies. `BOX86_LOG=1` changes timing enough to advance through archive loading and `preinit.ini`, but the clean safety flags do not. Even the advanced run produces no first draw/swap.

Requested next step: identify the most targeted way to distinguish a Box86 timing/dynarec translation issue from an ARMHF game-side state/timer loop without stacking broad flags. A one-variable test or a specific Box86 trace/breakpoint location is preferred.
