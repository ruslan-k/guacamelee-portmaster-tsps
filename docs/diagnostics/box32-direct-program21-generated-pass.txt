```text

```

The later duplicate attach sequence is:

```text
GUA-ATTACH program=21 shader=14 type=0x8b31 attach_size=1 last_vert=14 last_frag=0
GUA-ATTACH program=21 shader=19 type=0x8b30 attach_size=2 last_vert=14 last_frag=19
```

This confirms that numeric shader/program IDs are reused and must be interpreted with chronology.

## Source classification

Shader19 is a fragment shader:

```glsl
uniform vec4 vMult;
void main() {
    gl_FragColor = vMult;
}
```

Shader20's vertex source is:

```glsl
varying vec4 v_texcoord0;
void main()
{
    gl_Position = vec4(0.0, 0.0, 0.0, 1.0);
    v_texcoord0 = vec4(0.5, 0.5, 0.5, 0.5);
}
```

Classifier result:

```text
shader20 type=GL_VERTEX_SHADER
pos=1
zero_pos=1
texture2D=0
vMult=0
```

The literal zero-position source is not present in the pinned gl4es source tree or gl4es binary. It is therefore an application-provided/generated fallback source, not a hard-coded gl4es blit shader.

## Uniform evidence

All setter families were covered through common `GoUniformfv/GoUniformiv` paths. For program21:

```text
uniform name=vMult
type=0x8b52 (vec4)
location=0
value repeatedly=0,0,0,0
```

`glUniform1i` produced no program21 records because this pair has no sampler uniform. The zero value is the fragment output for shader19.

## Pixel correlation

At the first observed program21 draw:

```text
logical/native FBO=3/3
program=21
viewport=0,0,1280,720
scissor=disabled
color mask=1111
blend=0 depth=0 cull=0
PIXEL_AFTER_DRAW rgba=0,0,0,0
```

This is expected from the shader pair: all vertices are at one clip-space point and the fragment output is transparent black. This pass is proven non-visible and should not be “fixed” by forcing `vMult` or rewriting the shader.

The earlier conclusion “program21 zero uniform is the root cause” is superseded. It is a symptom/intentional fallback pass. The next relevant pass must be identified by finding the first game program with a non-zero `gl_Position` and a non-transparent fragment output.
